All 75 named queries are listed. Every runtime query is parameterized (`$name`), never built with string formatting. Reads go through `db.read` (GRAPH.RO_QUERY), writes through `db.write` (GRAPH.QUERY); `graphdispatch/db.py` is the only module that talks to FalkorDB.

**Timing:** the median of 20 runs (after one warm-up run) on graph `sjfd_test` with representative parameters, measured at generation time on a laptop. Not timed: the index and load queries (they run once when the seed is loaded) and queries that change state in a way that cannot be repeated meaningfully (`wipe_runtime`, `set_unit_status`, `dispatch`, `clear`, `expire_incidents`).

### `dispatch`


### `effective_requirements`

- Purpose: Incident type requirements plus requirements added by active hazards at the incident's address; hazards are grouped by (capability, kind) taking the max count per kind, so repeated hazards of one kind never double count.
- Kind: read
- Called from: graphdispatch/recommend.py: recommend (db.read)
- Median: 1.17 ms over 20 runs

```cypher
MATCH (inc:Incident {incident_id: $incident_id})-[:OF_TYPE]->(t:IncidentType) OPTIONAL MATCH (t)-[q:REQUIRES]->(c1:Capability) WITH inc, t, collect({cap: c1.name, need: q.count, source: 'base'}) AS base OPTIONAL MATCH (inc)-[:AT]->(:Address)<-[:AT]-(h:Hazard)-[:OF_KIND]->(k:HazardKind)-[r:ADDS_REQUIREMENT]->(c2:Capability) WHERE h.valid_from <= $now AND $now <= h.valid_to AND r.incident_type = t.name WITH base, c2.name AS cap, k.name AS kind, max(r.count) AS need, collect(h.hazard_id) AS ids WITH base, collect({cap: cap, need: need, source: 'hazard:' + reduce(acc = '', i IN ids | CASE WHEN acc = '' THEN i ELSE acc + ',' + i END) + ':' + kind}) AS added UNWIND base + added AS x WITH x WHERE x.cap IS NOT NULL RETURN x.cap AS cap, sum(x.need) AS need, collect(x.source) AS sources ORDER BY cap
```
